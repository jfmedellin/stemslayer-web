# P9 — Mixer: domain, AudioWorklet adapter, UI

Status: opened 2026-09-22. Delivery strategy: `ask-on-risk`; chain strategy: `feature-branch-chain` (continuing P7a/P7b/P8's convention). Developed locally on `feat/p7b-onnx-worker` (has P1..P8); publication base decided at closure.

## Objective

Implement real stem playback: the `AudioEnginePort` (`src/infrastructure/web-audio/`, an `AudioWorklet` mixing every lane from planar Float32 buffers with a shared cursor), the pure mixer domain (`src/domain/mixer/`: lane model, gain-from-percent, mute/solo resolution, loop range), the `openInMixer` use case that loads a track's stored stems into a mixer session, and the Mixer UI (lane strip, transport, keyboard shortcuts) that P8 already left a reachable-but-empty nav destination for.

## Problem / why

P1..P8 built everything up to a finished, stored stem set (`ready` tracks in the library) but nothing plays them back — Library's "Open in mixer" and the nav's "Mixer" destination both currently render `<PlaceholderPane title="Mixer">Coming soon.</PlaceholderPane>` (`src/ui/App.tsx`). P9 is the phase that makes the separated stems actually audible and controllable, porting the desktop mixer's exact behavior (`docs/decisions/feature-parity.md`'s Mixer section, translated from `test_mixer_controller.py`/`test_playback.py`) onto the Web Audio topology already decided in `docs/decisions/architecture.md`'s Runtime topology section.

## Scope

- **`src/domain/mixer/`** (pure TypeScript, no browser APIs, matching `domain/library`'s `track.ts` style): lane model derived from the loaded profile (`profile.lanes` order, not hardcoded to 4 — `feature-parity.md` "Lane set/order is derived from the loaded profile/manifest"); `gainFromPercent` (0–100% linear to 0.0–1.0, rejects non-finite/out-of-range/bool/non-numeric with a typed `mixer.invalid_volume` error — port `engine/mixer.py:7-15`, `gain_from_percent`); `effectiveGain` mute/solo resolution — **exact rule**: `muted OR (anySolo AND NOT thisLane.solo) → gain 0`, multi-solo supported (port `engine/mixer.py:49-57`, `effective_gains`); master gain as a separate 0–100% value applied after the lane-gain sum, clamped not refused on out-of-range; loop range (a start/end sample pair, or `null` for whole-track loop-to-0); skip/seek clamped to `[0, frameCount]`, exact `10.0` second skip constant; an unknown lane name still resolves to a fallback-render identity rather than throwing (`gui.py:97-99,151-164`); a lane name outside the currently published layout is refused by every mixer command (`mixer_controller.py:559-569`, `_stem_index`); a failed-to-load session falls back to the 4-lane Basic layout as an error placeholder (`mixer_controller.py:658-671`); async load uses a generation token so a stale/superseded load's result is discarded (`mixer_controller.py:175-236`).
- **`src/application/open-in-mixer.ts`** (new use case, following `separate.ts`'s style): given a `trackId`, reads the track from `CatalogPort`, reads every one of its lanes from `StemStorePort` (byte-identical WAV per lane, decoded with the existing `decodeFloat32Wav` codec from P5 — reuse it, do not re-decode via `AudioContext.decodeAudioData`, since the stored bytes are already the exact float32 planar PCM the mixer needs and re-decoding through the browser's audio decoder would risk sample-rate/resampling drift), builds a `MixerSession` (lane buffers + profile lane metadata, matching `docs/decisions/feature-parity.md`'s "absent lane" rule: a role lane — Rock's `guitar_center`/`guitar_sides` — with no detectable energy still plays as real aligned silence, fully controllable, labeled `"{LANE} · NOT IN THIS TRACK"` rather than hidden; detect absence the same way `assembleStemLanes`'s residual math would produce it, or define "absent" as every sample exactly 0 if that is simpler and equally correct — writer's call, document the choice), and calls `AudioEnginePort.load(session)`. A track whose stems fail to load falls back to the 4-lane Basic layout as an error placeholder per the domain rule above.
- **`AudioEnginePort`, real contract** (replace the `load(session: unknown)` placeholder with the concrete shape `open-in-mixer.ts` needs) **and its adapter** `src/infrastructure/web-audio/` — implements the topology `architecture.md` already decided, do not re-derive a different one: one `AudioContext`, one `AudioWorkletNode` (a real `AudioWorkletProcessor` module loaded via `audioContext.audioWorklet.addModule(...)`) that mixes every lane's planar Float32 buffers internally with one shared sample cursor; per-lane gain and the mute/solo-resolved effective gain are computed in the domain and pushed into the worklet as parameters (design the exact message/param protocol — see below); master gain is a separate native `GainNode` positioned *after* the worklet node's output, feeding `audioContext.destination`; loop range (restart/region) is handled *inside* the worklet (advancing the shared cursor), not via `AudioBufferSourceNode.loop`, since there is exactly one worklet node driving every lane already, not N separate buffer sources — this sidesteps `feature-parity.md`'s open question #4 (multi-lane synchronized seek) entirely: with one shared cursor inside one node, there is nothing to desynchronize. **Define the worklet's message/parameter protocol as its own first deliverable** (mirroring `src/infrastructure/onnx-worker/protocol.ts`'s precedent: a documented, typed contract before building against it) — at minimum: a `load` message carrying the lane buffers (transferred, not copied) and profile metadata; per-lane gain as either a dynamically-registered `AudioParam` per lane slot (`parameterDescriptors` is a static class member, so support up to the largest profile's lane count, e.g. 6) or an explicit `port.postMessage` gain-update command, whichever the writer determines is the more correct fit for sample-accurate mute/solo changes — document the choice and why; play/pause/seek/loop-region commands via `port.postMessage`; periodic (not per-render-quantum) progress messages back to the main thread for the playhead/time readout, batched so the audio thread isn't flooded.
- **Mixer UI** (`src/ui/mixer/`, following P8's established container/presentational precedent — `MixerPage.tsx` container + presentational lane/transport components, not the full atoms/molecules/organisms/templates/pages taxonomy `architecture.md`'s diagram sketches, matching what P8 actually shipped): six-lane-max strip (color ribbon per stem — reuse the existing stem-color tokens from `tokens.css`, including the two Rock guitar tints already defined), each lane showing its name, waveform (precomputed peak envelope, 2000 max-abs bins per lane — `feature-parity.md` "Peak/waveform envelope"; compute from the decoded planar PCM on load, a pure downsampling reduction, no new dependency needed), mute (`M`) and solo (`S`) pills, and a gain fader with its dB readout (map the 0–100% domain value to dB for display only — the domain itself stays percent/linear per `gainFromPercent`'s contract). One continuous playhead line spans the whole strip (a single absolutely-positioned element, not drawn per lane). A/B loop region markers on the shared timeline (draggable, matching the fetched Stitch screen's "A 00:48" / "B 01:36" markers — this extends `feature-parity.md`'s baseline "loop restarts at 0" into a settable region, which `design-reference.md` section 5 already accepts as the redrawn Mixer screen's own design, not a rejected deviation — see the design reconciliation note below). Transport bar: play/pause, −10 s / +10 s skip (exact `10.0` second constant), time readout `MM:SS / MM:SS`, master gain control with its dB readout, keyboard hints text. Spacebar toggles play/pause **only** when the active view is Mixer *and* a session can currently play (`(view, canPlay) => view === "mixer" && canPlay"`, bound globally, `preventDefault()` so it never scrolls the page — port `gui.py:180`, `space_toggles_playback`); left/right arrow keys map to the same ±10 s skip; a loop-toggle key (this task's own reasonable binding, matching the fetched screen's "L LOOP" hint). Track header: title/artist/duration/profile/lane-count/"separated {relative time} ago", "Back to library", "Export stems" (navigates to the Export destination only — Export itself is P10, out of scope here, same pattern as P8's Mixer/Export placeholders).

## Design reconciliation done before delegating (documented, not left implicit)

`feature-parity.md`'s Mixer row for "Loop" only describes whole-track repeat-to-0 ("the seam between passes stays inaudible"), with no A/B region language. The redrawn Stitch Mixer screen (fetched and read directly for this document, screen id `1ce928d6ca994ab7adebd38b99729b16`) shows explicit "A 00:48" / "B 01:36" loop-region markers, and `design-reference.md` section 5's own write-up of that same redrawn screen lists "playhead and A/B loop region" as part of what the screen gets right — not flagged in section 3's rejected-deviations table. Since `design-reference.md` is the later, more specific decision that reviewed this exact mockup and accepted it, this task treats the settable A/B loop region as the accepted, richer superset of `feature-parity.md`'s baseline loop behavior (a region loop degenerates to whole-track loop when A=0/B=end), not a Stitch-generic feature to strip out. If this reconciliation is wrong, it is cheap to correct later — the domain's `loop range` type already models it as a nullable start/end pair, so removing the "settable" UI affordance down to a single loop-whole-track toggle would not require reshaping the domain contract.
