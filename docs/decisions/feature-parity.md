# Feature Parity Inventory — Stemslayer Desktop → Stemslayer Web (T4)

Source read: `Tests/Portable/*.py` (20 test files + README), `SeparationWorker/engine/*.py`, `SeparationWorker/history.py`, `job_manager.py`, `model_manager.py`, `mixer_controller.py`, `gui_controller.py`, `instance_lock.py`, `paths.py`, `model_manifest.py`, `Compliance/registry.py` (skim), and `gui.py` (skim, ~2000 lines, for view structure/shortcuts/DnD/filters/export).

**Important finding surfaced during this pass:** in `gui.py`, the "hero" separation controls built in `_build_separation_view` — the profile `CTkSegmentedButton` (`self.profile_selector`), the lane chips (`self._chips_frame`), the status banner, and the **"Separate into N stems" button** (`self.action`, wired to `self._start` → `self.controller.start()`, `gui.py:763-786`) — are packed and then **immediately `pack_forget()`'d** (`gui.py:778-786`) and never re-packed anywhere else in the file. `self.controller` (`gui_controller.SeparationController`) never has `set_input_file()` called on it either. These widgets are only reachable through direct test attribute access (`test_gui_view_state.ProfileSelectorTests`, `test_gui_lane_rendering.ProfileSelectorTests`) — **a real user never sees or can click them**. The actual live "split view" flow is: drop a file / click "Browse file" (`self.input_button`, `_pick_input`) → `_choose_profile` dialog → `_confirm_library_add` → `SplitLibraryController.add()`, with progress/cancel/retry all surfaced through the library row, not through `gui_controller.SeparationController`. The parity table below is built from the **live** flow (`SplitLibraryController` + `JobManager` + `history.py`), and the dead hero controls are called out where relevant so the web rewrite doesn't spend effort reproducing unreachable UI.

Raw model stems are stored as IEEE float32 WAV without attenuation, limiting, or a peak-1 refusal; finite samples above 1 are preserved. This deliberately differs from the desktop encoder's peak guard because the web encoder is used during stem publication, before any mixer gain exists. The current Export copies those stored bytes unchanged. A future rendered mixdown should retain the separate reject-and-disclose-peak contract above rather than silently clipping.

## 3. Behaviors with no web equivalent yet (need a product-owner decision)

1. **Cross-tab coordination.** Desktop refuses a second launch outright (single-instance lock) before touching the DB. The web app has no such guard, and IndexedDB writes from two tabs aren't automatically serialized the way `HistoryStore`'s SQLite transactions are (`claim_identity`'s `BEGIN IMMEDIATE`, `test_history.test_concurrent_same_identity_adds_run_separation_exactly_once`). *Question: if a user opens the site in two tabs and drops the same file in both, is a duplicate/racing separation acceptable, or does the library need a `BroadcastChannel`/Web Lock API coordination layer?*

2. **Cancellation semantics for in-flight WASM/WebGPU inference.** Desktop cancellation is a real OS-level SIGTERM→SIGKILL of a Demucs subprocess (`job_manager.py` escalation), completing within a bounded few seconds even mid-inference. A `Worker.terminate()` is instant but blunt, and there's no equivalent to "the app's own close handler waits up to 8 seconds draining jobs" (`shutdown(deadline=8.0)`) — `beforeunload` doesn't actually block page teardown the same way. *Question: is `Worker.terminate()` (with no drain/grace period) an acceptable substitute for the desktop's bounded, escalating cancel/shutdown, or does the product want an explicit "your export will be lost" warning matching desktop's close-confirmation copy?*

3. **Multi-file drop / queue.** Desktop's drop handler silently discards every path but the first (`paths[0]`, `gui.py:1068-1072`) even though the underlying `JobManager`/library fully supports a FIFO queue of multiple jobs (proven end-to-end by `test_history.test_controller_propagates_queued_track_ids_in_fifo_order_as_the_running_job_drains`). *Question: should the web drop-zone match desktop's first-file-only limitation exactly, or take the opportunity to accept a multi-file drop (the backend queue already supports it)?*

4. **Multi-lane synchronized seek in Web Audio.** Desktop's `PlaybackEngine` seeks N already-open file readers together (`_seek_readers`) without reopening the output stream. Web Audio's `AudioBufferSourceNode` cannot seek in place — a synchronized seek means stopping and rescheduling N buffer sources at the same `currentTime` offset. *Question: is a brief (sub-frame, but technically-possible) desync risk across lanes during a fast scrub acceptable, or does this need a more careful design (e.g., a single `AudioWorkletProcessor` mixing all lanes internally, driven by one shared read cursor, closer to the desktop model)?*

5. **Storage-quota errors.** Desktop's temp cache and durable library both live on effectively-unbounded local disk, with only a time-based orphan sweep (6h) as housekeeping (`stem_cache.py`). A browser's IndexedDB/OPFS storage is quota-bounded and can throw `QuotaExceededError` mid-write, a failure mode with **no desktop analog** in any test file. *Question: what should happen when a separation or an export write hits a storage quota — refuse the job up front with an estimate, or let the write fail and surface an actionable error matching the existing `*.failed`/`*_incomplete` error taxonomy?*

6. **Whether "cache" and "library" collapse into one tier on web.** Desktop has two separate storage tiers: a temp, orphan-swept `stem_cache` (reused across identical inputs+pipelines) and a separate durable `library_root` managed by `HistoryStore`. Auto-opened results are tracked for cleanup on close; manually-loaded folders are not (`test_stem_lifecycle_integration.py`). Since the web app has no "load an arbitrary folder from disk" affordance, every result is inherently library-managed. *Question: does the cache/reuse dedupe key (`cache_key`) still need to exist as a separate concept from the library's own `(source_hash, pipeline_fingerprint)` dedupe key, or should they simply be the same key/store on web?*
